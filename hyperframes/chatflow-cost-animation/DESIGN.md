# 全技能总控单次运行成本动画视觉规范

## 画面目标

这是一支 16:9、单画布的节点运行解释动画。它只回答两个问题：

- 这一条 `赢单｜全技能总控 Chatflow` 在一次代表性运行里经过哪些关键节点？
- 每到一个节点，这一步有没有新增模型或工具供应商成本？

动画不比较两条 Chatflow，不讲利润、售价、V豆和后台架构，也不使用多场景转场。

## 本轮模拟路径

- 用户没有上传图片或文档。
- `skill_key = cold-email`，因此选中 `Skill｜新客开发信` Prompt。
- 前端 `model_key` 选择值为 `deepseek-v4-pro`。
- YML 中实际执行的 Agent 模型为 `deepseek-v4-flash`，计费身份必须以后者为准。
- Agent 在本轮模拟中成功调用 `Tavily Search` 和 `Tavily Extract`。

## 单画布结构

- 左侧：保留真实的三条并行支路——文件、知识库、Skill——并在同一画布汇合到模型路由、Agent 和 Answer。
- 右侧：固定成本账本。只有计费节点运行时，对应账本行才点亮。
- 底部：固定白话播报区。逐步解释“这里做了什么”和“本步是否新增成本”。
- 非计费的重复节点可以按支路归组，但计费资源必须保留精确 provider、model 或 tool name。

## 视觉语言

- 暖纸张背景、深绿账本、橙色计费提示，延续赢单现有成本页的视觉气质。
- 所有节点从一开始就在画布上，处于“等待”状态；运行时逐个点亮，不做换页。
- 绿色表示已运行但不直接计费，橙色表示本轮新增成本。
- 未触发的视觉模型保持灰色说明，绝不把“可能存在”表现成“已经收费”。

## 动效原则

- 节点状态和右侧账本行必须在同一个时间点变化，明确因果关系。
- 节点运行使用轻微放大、颜色变化和状态文字交替。
- 底部说明卡只做淡入淡出与轻微纵向位移。
- 所有动画由一条暂停的 GSAP 时间线控制，不使用随机数、当前时间、网络数据或无限循环。

## 成本口径

- RAG：本轮产生 `text-embedding-3-large` 查询 Embedding 成本；YML 已关闭 rerank，因此不记重排模型费。
- Agent：按实际执行节点的 provider、model、输入 tokens、输出 tokens 计费。
- Tool：只有出现成功的实际调用事件，才按调用次数或 credits 计费；不同工具分别归集。
- 用户输入、条件路由、模板、变量聚合和 Answer 节点不重复新增 LLM 或工具费用。
- 图片为空时，`gemini-3.5-flash` 视觉节点未执行，本轮不计费。
