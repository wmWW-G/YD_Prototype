# 赢单后台产品运营审阅

## 审阅范围

- 入口：`http://localhost:8765/#/admin/`
- 主后台页：`#/admin/home`、`#/admin/business`、`#/admin/user`、`#/admin/user-pool`、`#/admin/paid-pool`、`#/admin/sales`、`#/admin/active-user`、`#/admin/paid-user`、`#/admin/invited-user`、`#/admin/agent`、`#/admin/knowledge-base`、`#/admin/invite-code`、`#/admin/ai-character`、`#/admin/ai-model`
- 补充子状态：经营分析功能洞察、客服视角、用户字段配置、知识库新增、人设菜单管理、新增 AI 人设、AI 模型编辑

## 总体判断

当前后台已经有产品运营后台的雏形：能看用户分层、销售归因、代理渠道、邀请码、知识库、人设和模型，也有一页较有价值的经营分析。

但它还没完全成为运营每天能用的工作台。最大问题不是视觉，而是运营闭环不够：看到了用户、功能和成本，但没有把「异常发现 -> 分配责任人 -> 跟进动作 -> 转化结果 -> 下次复盘」串成一条可执行路径。

## 当前强项

- `经营分析` 的方向对，已经从单纯调用次数升级到 ROI、留存、付费提升、成本和功能象限。
- `用户` 分组清楚，公海客户、付费公海、活跃用户、付费用户、受邀用户和销售维度基本覆盖运营日常对象。
- `邀请码管理` 已经能表达销售发码、积分、归属、状态、兑换用户和过期时间。
- `字段配置` 对 User Preview 很有价值，可以让运营按阶段自由拼报表。
- `AI 人设管理` 和 `知识库管理` 覆盖了 AI 产品后台最核心的配置面。

## 主要问题

1. `#/admin/` 根路径没有进入后台，而是落回前台问一下。后台收藏、分享、口头交接时容易迷路。
2. `首页` 仍是「敬请期待」。运营打开后台第一屏没有今日待办、异常提醒、转化漏斗或关键经营摘要。
3. 多数用户分层页面仍是「名单 + 导出 + 模拟动作」，缺少跟进状态、负责人、下一步任务、跟进结果和关闭原因。
4. `User Preview` 数据很全，但偏分析宽表；`经营分析` 更像决策页。两者之间还缺跳转关系，例如从某个高成本功能跳到具体用户和调用明细。
5. `知识库管理` 只有文件列表和新增，缺少知识库质量、命中率、失败问题、关联人设、更新时间和可用性状态。
6. `AI 人设管理` 有配置字段，但缺少运营评价指标：使用量、满意度、转化贡献、失败率、Token 成本和关联功能。
7. `AI 模型管理` 过薄，目前只能编辑模型和思考层级，运营无法判断哪个模型贵、慢、差、稳。
8. 客服视角在经营分析里被禁止是合理的，但应该给客服一个自己的工作台入口，否则客服角色只剩提示文案。

## 优先建议

1. 先把后台首页做成运营驾驶舱：今日新增、今日付费、到期待跟进、异常失败、待分配公海、销售待办、功能成本预警。
2. 把用户分层页改成可推进的运营列表：每行增加负责人、跟进状态、最后动作、下一步时间、转化阶段。
3. 打通 `经营分析 -> 功能明细 -> 用户总表/活跃用户`，让运营能从一个问题一路追到具体用户。
4. 增强 AI 后台：人设和模型都要显示使用、成本、失败、满意度和转化贡献。
5. 统一后台入口：`#/admin/` 应重定向到 `#/admin/home` 或直接到 `#/admin/business`。
6. 给客服做一个轻量工作台：待处理用户、失败调用、待续费咨询、用户反馈和补积分记录。
